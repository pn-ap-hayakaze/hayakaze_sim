## 実行

```bash
cd prototype
npm install
npm test                    # 較正アサート（6シード）・乱数の独立性・DH の型・クラッチ係数
npm run validate            # 1シーズン回してリーグ水準・順位表・タイトルを表示
npm run validate -- 777     # シードを変える
npm run diag                # 個人成績の散らばり（防御率の標準偏差など）
npm run diag:levels         # 複数シードのリーグ水準を1枚の表に（較正表の元データ）
npm run diag:fatigue        # 疲労モデルの挙動
npm run diag:bullpen        # 救援の登板配分
npm run diag:usage          # 連投・完投・球数・登板間隔・盗塁企図の実測
npm run diag:clutch         # クラッチ係数の効き方
npm run typecheck
```

1シーズン（858試合）は約 130ms。1試合あたり 0.15ms。

## モデルの要点

### 打席の決定 — Odds Ratio Method
打者の率 b、投手の率 p、リーグ平均 l から `odds = (b/(1-b))(p/(1-p)) / (l/(1-l))` を
8つの結果カテゴリ（K, BB, HBP, HR, 3B, 2B, 1B, インプレーのアウト）それぞれで計算し、正規化する。
打者と投手の能力は対になって打ち消し合う:

| 打者 | 投手 | 結果 |
|---|---|---|
| ミート（良い打球を打つ頻度） | H/9 | インプレー安打全般（単打が中心） |
| パワー（打球の強さ） | HR/9 | 本塁打を中心に、二塁打・三塁打・単打にも |
| コンタクト | K/9 | 三振 |
| 選球眼 | BB/9 | 四球 |

パワーは本塁打だけの能力ではない。強い打球は内野を抜け、外野の間を割り、フェンスを越えるので、
全インプレー安打に配分する（本塁打 0.7 / 三塁打 0.3 / 二塁打 0.45 / 単打 0.15）。

**水準と散らばりは別の定数で制御する。** `LEAGUE_AVERAGE`（50 vs 50 で出る結果分布）がリーグ全体の水準を、
`SLOPE`（能力値+10 でロジットがどれだけ動くか）が個人差の散らばりを決める。出場している選手の平均が 50 なら、
リーグの実測はほぼアンカーに一致する（Jensen 効果で打率にして +.003 ほど上）。

**注意:** 各プロファイルで `OUT_IN_PLAY` を残差として計算してはいけない。能力差が二重に効き、防御率0.52の投手が生まれる。
正規化は `combine()` で一度だけ行う。

### クラッチ — 得点圏でミートに掛かる係数
得点圏（二塁または三塁に走者）では、打者のミートと投手の H/9 に係数 `f(clutch) = 1 + 0.09 × (clutch − 50) / 10` を掛ける。
`f(50) = 1.0`。置換ではなく乗算なので、ミートが高い選手ほど得点圏での上振れの絶対値が大きい（勝負強さは実力の増幅）。

- 傾き 0.09 の根拠: ミート1点あたりの wOBA 感度は約 1.4 ポイント。クラッチは σ10 で生成するので、
  真のクラッチ才能（得点圏 wOBA − 通常 wOBA の選手間 σ）がスタメンで約 7 wOBA ポイントになる（6シードで 5.6〜7.3、平均 6.6）。
  The Book のクラッチ才能の推定は約 8 ポイント。レビュー時のオフセット案 `meet + 0.35×(clutch−50)` は σ≈5 で届かない
- 生成分布は `70 − Gamma(4, 5)`（`player/clutch.ts`）。平均 50・σ10 を保ちつつ上限 70、65 超は約 1.4%、70 超は 0。
  σ を 10 に保つのは 20-80 スケールとの 1:1 対応を崩さないため。「そうそう高くならない」は分布の形で表現する
- ミート・階層と独立に生成する。投手のクラッチも hits と独立に同じ分布で引き、同型の係数を掛ける
- 以前の「クラッチでコンタクトを置き換える」方式は、得点圏の選手間分散が実測の 2.5 倍（真の σ 約20打率ポイント）になり、
  階層差（主砲と控え）とプラトーン差（左右別ミート）が得点圏で消えていた。係数型では階層差が 1.00〜1.02 倍、
  プラトーン差の相関 0.995 以上で保たれる。リーグ得点は全員クラッチ50のときと ±1% 以内で一致する
- 投手側は同じ係数でも効きが打者の約 0.4 倍（才能 σ 2.4〜3.1）。`pitcherHit` の傾きが意図的に緩いためで、
  規定級投手の（防御率 − FIP）σ は係数なし 0.53 → あり 0.54〜0.57 とほぼ変わらない

### 指名打者 — 守備位置ではなく打順の枠
`POSITIONS` は守備位置 9 つのまま、`LINEUP_SLOTS = [...POSITIONS, 'DH']` を打順の枠として別に持つ。
`POSITIONS` に DH を足すと `FieldingByPosition` が全選手に無意味な「DHの守備力」を持ってしまう。
`BattingStats.appearances` に枠ごとの出場試合数を記録し、WAR の守備位置補正は主ポジションではなくこの内訳で按分する
（遊撃手が DH で休んだ日には遊撃の加点はつかない）。DH の補正値は FanGraphs の MLB 値 −17.5 ラン/162試合。

DH の有無は `LeagueConfig` のリーグごとの設定で、本拠地リーグのルールを試合に適用する。既定は**両リーグ DH**（設計決定）。
試合シミュレーション（`game.ts`）はリーグの存在を知らず、`GameRules { dh }` を受け取るだけ。

### リーグ構成 — 球団数・試合数をハードコードしない
`LeagueConfig`（球団リスト・リーグ定義・同一リーグ対戦数・交流戦対戦数）から、日程・年間試合数・規定打席・順位表を導出する。
NPB 既定は 12球団 2リーグ、25×5 + 3×6 = 143 試合。将来の球団追加・リーグ再編はこの設定の差し替えで表現する。

### 乱数 — 用途別・試合別の独立ストリーム
試合用の乱数は `hash(masterSeed, GAME, year, day, gameId)` から試合ごとに派生させる（murmur3 の fmix32、`rng.ts`）。
ロスター生成・日程生成も同じ仕組みで別ストリーム。故障・スカウト観測・成長・AI 意思決定の派生口も用意してある。
`Rng.serialize()` / `Rng.restore()` で状態をセーブに書ける。

以前は単一の `Rng` をシーズン全体で共有していて、10日目に `rng.next()` を1回余分に呼ぶだけで12球団すべての勝敗が変わり
優勝球団が入れ替わった（セーブ&ロードで打順を触れば残りシーズンを引き直せる状態）。現在は、ある試合の乱数消費を変えても
同じ日の他の試合と、翌日以降のその2球団が関わらない試合は結果が変わらないことをテストで保証している
（疲労は試合をまたいで因果的に伝播するので、その2球団の以後の試合が変わるのは正しい挙動）。

### 投手能力の2層構造
- 素材: 球種ごとの スピード／変化／コントロール。投手全体の値はその平均
- 結果指標: H/9, HR/9, K/9, BB/9 を素材から派生（`arsenal.ts`）。シミュレーションはこちらだけを使う。クラッチは素材から派生させず独立
- 直球の「変化」は伸び。高いほど空振りを取れる（K/9 に直接寄与）
- 遅い方が良い球種（カーブ・チェンジアップ等）は直球との速度差でスピードを評価する
- 各球種の変化は「その球種としての質」（50=平均）。絶対的な変化量にすると平均が40にずれて較正が崩れる

### 疲労
- 登板で `22 + 球数×0.7` の疲労、毎日 `10 + 回復×0.2` 回復（回復は独立した能力値。`season.ts` の `dailyRecovery`）
- 疲労は 球数上限の縮小・能力低下・継投優先度の低下 に効く。60以上は登板不可
- 連投日数のルールは置かない。疲労が体力の限界を決める

### ブルペンの役割
守護神1・セットアッパー3・中継ぎ4。勝ちパターン（7回以降、同点〜3点リード、または1点ビハインド）はセットアッパー、
それ以外は中継ぎ、大差は下位の中継ぎ。役割を固定しないと能力の高い救援が年間90登板を超える。

### 打席イベントとセイバーメトリクス
すべての打席を `PlateAppearanceEvent`（前後の走者・アウト・得点差・結果）として記録する（1シーズン約64,000件）。
これを元に **得点期待値表（RE24）と線形ウェイトをシミュレーション自身から導出**し、wOBA → wRAA → wRC+ を計算する。
外部の定数を借りないので、リーグ環境を変えてもウェイトが自動で追従する。

- `metrics/runExpectancy.ts` — RE24、ΔRE による線形ウェイト。サヨナラで打ち切られた半イニングは標本から除外し、
  標本の少ないセルは事前表へ縮約する。「3アウト目に得点」という規則上ありえない遷移を数えて試合ロジックのバグを検知する
- `metrics/advanced.ts` — wOBA / wRC+ / FIP / WAR。WAR は FanGraphs 方式:
  野手 = (wRAA + 走塁 + 守備位置補正 + リーグ補正 + 代替水準) / RPW、代替水準は 570勝/2430試合 を RPW で得点換算。
  投手 = (平均との差[勝/試合] + 代替水準[勝/試合: 先発 .12、救援 .03]) × IP/9。守備は未算入（打球の層が入ってから）
- `metrics/percentile.ts` — Baseball Savant 風のパーセンタイル（能力値も成績も同じ仕組みで 1〜100 に）
- `metrics/leagueLevel.ts` — リーグ水準（較正テスト・診断の共通部品）
- `metrics/clutchAnalysis.ts` — クラッチ才能の解析値（実測は打席数の二項ノイズが才能の5倍あり読めないため、能力値から計算する）

導出された wOBA ウェイト（seed 20260915）: 単打 .875 / 二塁打 1.301 / 三塁打 1.607 / 本塁打 2.300 / 四球 .733。
MLB の公表値（.88 / 1.25 / 1.58 / 2.03 / .69）に近い。得点環境が低いぶん長打の相対価値が高い。
野手・投手の WAR 合計は 201 / 155（FanGraphs の配分から計算した目標は 201 / 152）。

これらの式は多観点レビュー＋反証（Workflow）で検証した。当初の実装には、投手の代替水準を「失点の割合」と
取り違える（投手 WAR が定義の44%）、野手の代替水準が旧近似値、リーグ補正の欠落、という3つの式の誤りと、
併殺で三塁走者が消える・3アウト目の併殺でも得点が入る・サヨナラで試合が終わらない、という3つの試合進行の
バグがあり、いずれも修正済み。`npm run validate` の健全性チェックにこれらの再発検知を含めてある。

将来: 打球の質（種類×強さ×方向、Statcast 的な barrel / hard-hit 相当）を中間層として追加し、
反応（前後左右）・肩・パワーの定義を個々の守備機会に結びつける。WAR の守備成分はその上に載せる。

### 2026-09-16 の再較正: 何を変えたか

両リーグ DH に切り替えた時点（現行定数のまま）で、6シード平均が 打率 .254 / 出塁率 .323 / OPS .709 / R/G 3.98 /
防御率 3.58 / WHIP 1.351 と目標上限に乗った。原因は水準の変化: セ球場で打席に立っていた投手（wOBA ≈ .200、全打席の約 5.5%）が
控え野手（wOBA ≈ .300）に置き換わり、リーグ wOBA が約 +14 ポイント上がった。

**変えたのは `LEAGUE_AVERAGE`（アンカー）だけで、`SLOPE` は変えていない。**

| 定数 | 変更前 | 変更後 |
|---|---|---|
| BB | .078 | .075 |
| HR | .0215 | .021 |
| 2B | .039 | .038 |
| 1B | .164 | .160 |
| OUT_IN_PLAY | .4925 | .501 |
| K / HBP / 3B | .19 / .01 / .005 | 変更なし |

理由: `SLOPE` は母集団の平均が 50 なら水準を一次では動かさない（動くのは散らばり）。水準を `SLOPE` で直そうとすると、
個人成績の散らばり（首位打者・本塁打王・防御率σ）を壊すか、打者側と投手側の非対称（batterHR 0.33 vs pitcherHR −0.16、
batterK −0.23 vs pitcherK 0.12）を深めるかのどちらかになる。この非対称は防御率の散らばりを合わせるために入れたものだが、
Odds Ratio 法の「打者と投手が打ち消し合う」安定性を弱め、多シーズンでの得点環境の漂流の原因にもなっているので、これ以上深めない。
アンカーを「50 vs 50 = NPB 平均」に置き直すことで、「50 = 出場している選手の平均」という能力値の基準と、アンカーの意味が
DH 化で初めて素直に一致する。

|---|---|---|
| 打率 | .254 | .248 |

| 1試合平均得点 | 3.98 | 3.74 |

## 既知の簡略化（次段階で扱う）

- 野手の交代・休養がない。スタメン9人が全試合に出るため、規定打席到達者が現実の3倍いる。
  wRC+ 首位が 190〜200、WAR が 8〜10 とやや大きく出るのはこれが一因（打席数が現実の首位打者より 5〜10% 多い）
- 走塁モデルが粗い（単打・二塁打での進塁確率は定数ベース、犠飛・進塁打も定数）。RE24 の一塁走者の価値が
  MLB より 10% ほど低いのはここに由来する可能性がある。打球の層を入れる際に作り直す
- 走塁の WAR は盗塁・盗塁死の定数評価のみ。守備位置補正は FanGraphs の MLB 値をそのまま使う（NPB の DELTA 値は三塁の符号が逆、
  左右翼が非対称、DH −15.1。差し替えは実装フェーズ）
- 勝敗投手は常に先発に付く。救援の勝敗・ホールドは未実装
- 自責点は「失策の後にそのイニングで入った点は全部非自責」の簡略ルール
- 先発ローテは固定6人。故障・降格・入れ替えがない。支配下ロスターは野手17・投手14
- 故障、成長、二軍、契約、ドラフト、ポストシーズンは範囲外
- リーグ平均のアンカーは固定定数。多シーズンを回すと出場層の平均が 50 から漂流し得点環境が動くので、
  毎プレシーズンに実出場層の加重平均へ差し替える（決定済み、実装フェーズ）
- DH 解除（試合中に DH を失う）は未実装。`Lineup.dh` と `GameRules.dh` で受け皿だけある
- 起用 AI（オーダー・継投）は真の能力値を読んでいる。推定値ビューを引数で受ける形への変更は実装フェーズ

## 既知の問題（実測値、2026-09-16。修正は実装フェーズ）

`npm run diag:usage` の6シードの実測。目標は `npb-calibration-targets` の値。

| 項目 | 実測（1チーム年、6シードの範囲） | 目標 | 原因 |
