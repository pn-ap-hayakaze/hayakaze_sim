# エンジン検証プロトタイプ

NPB ペナントレースシミュレーションの **シミュレーション部分だけ** を先行実装し、
出力される成績が現実の NPB に近いことを確認するためのプロトタイプ。
UI・セーブ・GM 機能は含まない。

正式なドキュメント（`docs/`）と実装は、このプロトタイプで妥当性を確認したうえで進める。

## 実行

```bash
cd prototype
npm install
npm run validate            # 1シーズン回してリーグ水準・順位表・タイトルを表示
npm run validate -- 777     # シードを変える
npm run diag                # 個人成績の散らばり（防御率の標準偏差など）
npm run diag:fatigue        # 疲労モデルの挙動
npm run diag:bullpen        # 救援の登板配分
npm run typecheck
```

1シーズン（858試合）は約 130ms。1試合あたり 0.15ms。

## モデルの要点

### 打席の決定 — Odds Ratio Method
打者の率 b、投手の率 p、リーグ平均 l から `odds = (b/(1-b))(p/(1-p)) / (l/(1-l))` を
8つの結果カテゴリ（K, BB, HBP, HR, 3B, 2B, 1B, インプレーのアウト）それぞれで計算し、正規化する。
打者と投手の能力は対になって打ち消し合う:

| 打者 | 投手 | 結果 |
|---|---|---|
| ミート | H/9 | 単打・二塁打 |
| パワー | HR/9 | 本塁打 |
| コンタクト | K/9 | 三振 |
| 選球眼 | BB/9 | 四球 |

得点圏（二塁または三塁に走者）では、打者はコンタクトの代わりにクラッチを、投手は H/9 の代わりにクラッチを使う。

**注意:** 各プロファイルで `OUT_IN_PLAY` を残差として計算してはいけない。能力差が二重に効き、防御率0.52の投手が生まれる。
正規化は `combine()` で一度だけ行う。

### 投手能力の2層構造
- 素材: 球種ごとの スピード／変化／コントロール。投手全体の値はその平均
- 結果指標: H/9, HR/9, K/9, BB/9 を素材から派生（`arsenal.ts`）。シミュレーションはこちらだけを使う
- 直球の「変化」は伸び。高いほど空振りを取れる（K/9 に直接寄与）
- 遅い方が良い球種（カーブ・チェンジアップ等）は直球との速度差でスピードを評価する
- 各球種の変化は「その球種としての質」（50=平均）。絶対的な変化量にすると平均が40にずれて較正が崩れる

### 疲労
- 登板で `22 + 球数×0.7` の疲労、毎日 `10 + 回復×0.2` 回復（回復は独立した能力値）
- 疲労は 球数上限の縮小・能力低下・継投優先度の低下 に効く。60以上は登板不可
- 連投日数のルールは置かない。疲労が体力の限界を決める

### ブルペンの役割
守護神1・セットアッパー3・中継ぎ4。勝ちパターン（7回以降、同点〜3点リード、または1点ビハインド）はセットアッパー、
それ以外は中継ぎ、大差は下位の中継ぎ。役割を固定しないと能力の高い救援が年間90登板を超える。

## 既知の簡略化（次段階で扱う）

- 野手の交代・休養がない。スタメン9人が143試合すべてに出るため、規定打席到達者が現実の3倍いる
- 勝敗投手は常に先発に付く。救援の勝敗・ホールドは未実装
- 自責点は「失策の後にそのイニングで入った点は全部非自責」の簡略ルール
- 先発ローテは固定6人。故障・降格・入れ替えがない
- 故障、成長、二軍、契約、ドラフト、ポストシーズンは範囲外
- 交流戦の DH は本拠地リーグのルールに従う（実際の NPB と同じ）
